Upper boundO(g)Never grows faster than c·g(n). Read it as the worst case.
Lower boundΩ(g)Never grows slower than c·g(n). Read it as the best case.
Tight boundΘ(g)Both at once. Only exists when best and worst grow the same way.

Why O = Ω = Θ in every cell: the position is fixed (front or back), so the number of steps is one exact formula of n, such as n+1 or 1. The same formula is both the best and the worst case, so the upper and lower bounds meet and Θ exists. The pattern to remember: work at the front of an array costs Θ(n) because everything shifts; work at the back costs Θ(1), except Access, Replace, Next and Previous, which are Θ(1) everywhere.

The three definitions (from Lecture 07, slide 36)

f(n) = O(g(n)) there exist c and n₀ with f(n) ≤ c·g(n) for all n ≥ n₀. c·g(n) is an upper bound.

f(n) = Ω(g(n)) there exist c and n₀ with f(n) ≥ c·g(n) for all n ≥ n₀. c·g(n) is a lower bound.

f(n) = Θ(g(n)) there exist c₁, c₂ with c₂·g(n) ≤ f(n) ≤ c₁·g(n) for all n ≥ n₀. A tight bound.

How the course uses them on code: work out the step count for the worst input and give its O; work out the best input and give its Ω. If both land on the same g(n), the algorithm is Θ(g(n)) for every input. If they differ (linear search: Ω(1), O(n)) there is no single Θ, although you can still say “the worst case is Θ(n)”.

Rules that answer 90% of code questions

  • Drop constants: 5n → Θ(n). Quiz Q12’s inner loop runs 5 times, so it is a constant.
  • Keep the leading term: 3n² + 2n + 33 → Θ(n²).
  • Loops one after another add: n + n = 2n → Θ(n) (Quiz Q9).
  • Nested loops multiply: n · n → Θ(n²); n · 5 → Θ(n).
  • Halving or doubling the counter: Θ(log n).
  • Early return / break on found: best and worst split, so give Ω and O separately.
